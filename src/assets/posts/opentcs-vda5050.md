OpenTCS（Open Transportation Control System）是一款开源的运输调度系统，可用于智慧园区（智能工厂）场景。我们基于它打造了相应的解决方案（平台），涵盖内核架构、适配改造、应用场景等多个方面，本文做一个整体梳理。

![OpenTCS 智慧园区调度系统](/images/blog/opentcs/1.png)

## 内核核心架构与功能

内核负责整个调度系统的决策中枢，由三个核心组件协同工作：

- **Dispatcher（订单调度器）**：分配运输任务给车辆，决定「哪辆车做哪个订单」；
- **Router（路径规划器）**：计算车辆行驶的最优路径，决定「车辆走哪条路」；
- **Scheduler（资源调度器）**：管理路径上的互斥资源，决定「车辆何时能走这条路」。

内核采用事件驱动架构，核心事件包括「创建 TransportOrder」「车辆到达指定地点」「车辆状态变更」等，各组件围绕事件流转完成调度闭环。

此外，系统支持多种常见业务逻辑，例如：电量低于 30% 时自动充电、无订单时自动寻找停车位、到达指定地点装货卸货、通过某路径时开门关门、线边仓储位锁定、电梯上下楼等。

## 外部接口与管理工具

对外提供 4 类标准接口，供上层系统与客户端集成：

- Java RMI
- Web API（HTTP / REST / WebSocket）
- TCP/IP XML
- 事件推送

通过这些接口，可以对接 WMS / MES 等上层系统、自定义客户端以及 Web 应用。同时配套一套管理工具：

- **ModelEditor**：供技术人员进行工厂模型导入、编辑和上传；
- **KernelControlCenter**：用于管理车辆和外围设备；
- **OperationsDesk**：供工厂管理员进行调度订单管理、查看车辆调度总览视图。

## 平台适配改造

在开源内核基础上，我们做了针对性的适配改造，落地为平台解决方案：

- **内核改造**：实现内核集群调度、工厂模型持久化与数据恢复；基于 MQTT 协议改造车辆和外围设备通信适配器，支持指令下发和状态上报；
- **平台开发者后台**：支持应用关联多个工厂模型、工厂模型管理，以及内核日志数据（运输订单、车辆轨迹）查询。

## 基础数据与核心对象

- **工厂模型**：包含定位点类型、目标点位、中途点位、链接、车辆、外围设备等；
- **运输订单**：包含目的地设置、API、生命周期、结构和处理逻辑等。

## 应用场景

- **智慧园区（智能工厂）模板应用**：提供用户鉴权管理、工厂模型管理、日志查询、知识库管理、访客管理等功能；
- **迎宾机器人上位机**：支持填写访客信息记录表、对接门闸系统（响应访客拦截事件、完成信息填写后触发开门信号）。

## 在 Agentic 项目中的规划

调度系统可基于 OpenTCS 或 VLA 自主决策，由开发者后台统一配置，目前处于未开始状态。

## 小结

以 OpenTCS 内核为底座，结合 Dispatcher / Router / Scheduler 的调度模型与事件驱动架构，再通过 MQTT 适配器改造与开发者后台，可以快速落地一套面向智慧园区的机器人调度解决方案。
