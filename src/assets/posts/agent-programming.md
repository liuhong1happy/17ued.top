Agent 编程是软件开发领域一个新兴的方向，它改变了传统的开发模式，消除了软件开发工程化思想带来的人员庞大、巨大沟通成本等弊端。

Agent 编程的主要思想仍然离不开现有的开发体系，贯穿需求定义、产品设计、编码实现、测试部署、生产运维等诸多环节。下面讲解如何搭建一套 Agent 编程思维。

## 需求定义

需求定义来源于用户的诸多要求，结合工程师理解形成文档，这类文档通常不会涉及太多技术内容。这是工程师参与感最强的环节，整体需求定义来自工程师的大脑和掌握的用户需求。

## 产品设计

产品设计包含的内容比较多：业务流程设计、数据库设计、产品 PRD 设计、UI 界面设计、前后端开发和软件测试框架搭建，以及对部署和运维的简单描述。产品设计完全可以交给 AI 完成，我们只需要 Review 即可。

## 编码实现与自动化测试

编码实现主要靠 N 多轮反复对话，让 Agent 快速实现产品设计的所有内容。产品设计越丰富，Agent 输出的内容就越收敛——此时你会看到之前的工作没有白费，快速转换为开发成果。你只需要和 Agent 反复对话，它就可以自动编码、自动调试、自动测试。

这里需要让 Agent 编写单元测试、集成测试和端到端测试，通过建立好的自动化测试架构，让 Agent 编程逐渐收敛，避免带着问题上线。自动化测试脚本需要你非常认真地 Review，而不是简单扫一眼，要确认 Agent 是否真的帮你完善好了自动化测试的流程和内容。

## 主动测试与验收

编码阶段的自动化测试已经帮助我们修复了绝大部分问题，接下来需要人为主动测试：运行本地调试程序、打开相应界面、进行需求验收。不符合逻辑的记录并返工，符合逻辑的在 TODO 列表中勾选掉，避免重复开发。

## 版本收敛与敏捷开发

庞大的工程往往不是几轮对话就能解决的，需要反复沟通。如果放任 Agent 一直发散，去跟踪所有问题和所有内容，是非常危险的处理方式。我们需要让 Agent 建立一个整体框架的文件目录结构，规定每个阶段需要读取哪些大致内容。此外还要借鉴敏捷开发思想，按版本逐个定义小批量的开发内容，逐版本收敛开发内容。

## 部署与 CI/CD

编码阶段只是对程序进行调试，现在开始部署。部署脚本同样让 Agent 帮我们写好，准备好服务器后把密码告诉它，它就能快速搭建好部署环境并完成部署。如果你有使用 CI/CD 的习惯就更好了：用 git 仓库集成 CI/CD，配置好构建服务器，让构建服务器完成打包、推送和部署，所有代码提交都将实实在在地转化为可见成果。

## 线上运维

简单测试和部署完成后，工作仍未结束。我们要时刻监听线上程序的运行状态——是否出现慢 SQL、是否服务崩溃、服务器是否罢工等。可以通过 Agent 快速搭建一套线上运维工具，帮助我们迅速发现问题。
